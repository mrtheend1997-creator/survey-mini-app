# Языки: узбекская новая латиница, узбекская кириллица, русский

## Что есть в приложении

| Код | Язык | Где виден |
|-----|------|-----------|
| `uz` (uz-Latn) | Özbekça, латиница. Интерфейс написан новым алфавитом (Ö, Ğ, Ş, Ç) | по умолчанию |
| `oz` (uz-Cyrl) | Ўзбекча, кириллица | переключатель «Özb · Ўзб · Рус» |
| `ru` | Русский | переключатель |

* Переключатель стоит в шапке приложения, в админ-панели и **прямо в опросе**. Язык меняется сразу, без перезапуска: ответы, номер вопроса и переходы не сбрасываются.
* Выбранный язык хранится на сервере у каждого Telegram-пользователя. Кто уже выбирал «uz» или «ru», остаётся на своём языке (`uz` теперь показывается новой латиницей).
* Код `oz` — принятое на узбекских сайтах обозначение кириллицы. Он двухбуквенный, поэтому существующие колонки `users.language` и `responses.language` не менялись.

## Тексты опросов

* У каждого текста (название, описание, финальное сообщение, вопрос, подсказка, вариант, строка таблицы, подписи шкалы, единица измерения, цель сбора контактов, область/район, приветствие бота) есть три поля: UZ, ЎЗ, RU.
* Достаточно заполнить один язык. **Ничего не переводится и не транслитерируется автоматически.** Если перевода нет, участник видит текст на другом языке (кириллица → латиница → русский; русский → латиница → кириллица) и короткую пометку «🌐 часть текстов ещё не переведена».
* В конструкторе пустой язык подсвечивается жёлтым («Киритилмаган / Не заполнено»), у вопроса стоит метка «🌐 Нет перевода: ЎЗ, RU», вверху — сводка.
* Переходы между вопросами привязаны к ID варианта ответа, а не к тексту, поэтому работают одинаково на всех языках.

## Новая латиница (O‘→Ö, G‘→Ğ, Sh→Ş, Ch→Ç)

Правила взяты из задания (закон O‘RQ-1184 от 21.10.2026, вступает в силу 22.04.2027). **Текст закона мы проверить не смогли** — правила реализованы так, как они описаны в задании.

* Интерфейс уже написан новым алфавитом.
* Старые тексты опросов **не меняются сами**. Администратор переводит их сам:
  * кнопка **«Ö»** рядом с полем UZ — переводит одно поле;
  * кнопка **«Ö Yangi lotin alifbosiga ötkaziş»** в конструкторе — показывает список всех изменений «было → станет»; переводятся только отмеченные строки. Изменения попадают в черновик, участники увидят их после «Опубликовать». Уже опубликованные версии и собранные ответы не меняются.
* Учтено: все формы апострофа (‘ ’ ʻ ʼ ' `), заглавные буквы (Sh/SH → Ş), раздельное «s’h» (Is’hoq → Ishoq), тутуқ белгиси (ma’no, e’lon) остаётся. Ссылки, e-mail, @username и явно иностранные слова (с w или с c не из ch: Microsoft, Excel) не трогаются. Имена и бренды типа «Chrome» проверяйте в списке перед применением.

## Excel

Язык выгрузки = язык интерфейса администратора (UZ, ЎЗ или RU). Формат листов прежний. Unicode сохраняется (ö ğ ş ç ў қ ғ ҳ). Свободные ответы участников выгружаются в точности как написаны.

## Telegram-бот

* Приветствие редактируется в «Бот созламалари» на трёх языках. Режим «Фойдаланувчи тилида» отправляет приветствие на языке, который человек выбрал в приложении; «Барча тилларда бирга» — все заполненные языки одним сообщением.
* Если сохранённое ранее приветствие не имело кириллицы, кириллическим пользователям уйдёт ваш узбекский (латинский) текст — встроенный текст ничего не подменяет.
* Telegram передаёт боту только код «uz», без различия латиницы и кириллицы, поэтому команды и кнопка меню оставлены нейтральными («FTI Survey»).

# Развёртывание на Render: пошагово

### Что меняется в базе

Миграция `0009` **только добавляет 8 пустых колонок** `…_oz` (кириллица) в таблицы `surveys`, `questions`, `options`, `regions`. Никакие строки не удаляются и не изменяются, ID не меняются. В PostgreSQL такое добавление занимает доли секунды. Старая версия кода продолжает работать с новыми колонками (у них значение по умолчанию), поэтому во время переключения ответы не теряются.

Проверено на копии PostgreSQL с данными, созданными текущей рабочей версией (завершённые и незавершённые анкеты, переходы): до и после миграции все таблицы совпали построчно (ID, связи, содержимое); незавершённая анкета продолжилась после обновления на кириллице и сохранилась; откат миграции оставил все ответы, включая новые.

### Шаг 1. Резервная копия (обязательно, делаете вы)

На бесплатном тарифе Render **сам резервные копии не делает**, поэтому копию нужно снять вручную:

1. Render → ваша база PostgreSQL → **Connect** → скопируйте **External Database URL**.
2. На компьютере с установленным PostgreSQL (команда `pg_dump`, версия не ниже версии базы) выполните:
   ```
   pg_dump "ВСТАВЬТЕ_EXTERNAL_DATABASE_URL" -Fc -f fti-backup-ДАТА.dump
   ```
3. Проверьте, что файл не пустой (обычно от сотен КБ). Сохраните его в надёжном месте.
4. (Желательно) Проверьте, что копия восстанавливается — в отдельную пустую базу, **не в рабочую**:
   ```
   createdb fti_restore_test
   pg_restore -d fti_restore_test fti-backup-ДАТА.dump
   ```

Если на тарифе Starter/Basic и выше — достаточно нажать **Backups → Create export** в Render.

### Шаг 2. Цифры «до»

На том же компьютере подключитесь к базе командой `psql "ВСТАВЬТЕ_EXTERNAL_DATABASE_URL"` (или любым клиентом PostgreSQL), выполните запрос и сохраните результат:

```sql
SELECT 'surveys', count(*) FROM surveys UNION ALL
SELECT 'questions', count(*) FROM questions UNION ALL
SELECT 'options', count(*) FROM options UNION ALL
SELECT 'responses_completed', count(*) FROM responses WHERE status='completed' UNION ALL
SELECT 'responses_in_progress', count(*) FROM responses WHERE status='in_progress' UNION ALL
SELECT 'answers', count(*) FROM answers UNION ALL
SELECT 'users', count(*) FROM users UNION ALL
SELECT 'questions_with_jumps', count(*) FROM questions WHERE logic IS NOT NULL UNION ALL
SELECT 'max_answer_id', max(id) FROM answers;
```

### Шаг 3. Обновление

Слить Pull Request в `main`. Render сам соберёт новую версию и при запуске выполнит `alembic upgrade head`.
По документации Render веб-сервис без постоянного диска обновляется без простоя: старая версия обслуживает пользователей, пока новая не запустится; если новая не запустилась — остаётся старая. На бесплатном тарифе сервис «засыпает» при простое, и первый запрос после сна ждёт около минуты — это не связано с обновлением. Полное отсутствие простоя мы на вашем аккаунте не проверяли.

### Шаг 4. Цифры «после» и проверка

1. Повторите запрос из шага 2: все числа должны совпасть (или вырасти, если за это время кто-то отвечал), `max_answer_id` не меньше прежнего.
2. Откройте приложение в Telegram: переключите Özb → Ўзб → Рус на главной и внутри опроса — ответы на месте.
3. Админ-панель → любой опрос → «Excel юклаб олиш» — файл открывается.
4. Отправьте боту `/start`.

### Откат (если что-то пошло не так)

* Данные при откате **не трогаются**. Не используйте восстановление резервной копии поверх рабочей базы — это стёрло бы ответы, полученные после обновления. Копия из шага 1 нужна только на случай настоящей аварии.
* Кнопка **Rollback** в Render для этой версии не сработает: старая версия не знает миграцию `0009` и не запустится (рабочей при этом останется текущая версия). Безопасный откат — новая версия кода «как раньше», но с сохранённым файлом миграции `0009`: напишите в проект, это готовится за несколько минут, колонки и уже введённые кириллические тексты остаются в базе.
